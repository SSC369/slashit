## 1. What works when this lands

A session the API rejects, or one Supabase cannot refresh, ends on its own. The
user lands on Sign in with "Your session expired. Sign in again to continue.",
and after signing in returns to the page they were on. Nothing from the ended
session stays in the app.

## 5. Internal contracts

```ts
// sessionExpiry.ts
export type SignOutReason = "EXPIRED" | "USER";

/** Runs at most once until the next sign-in, however many requests fail
 * together. Local scope: other devices keep their sessions. */
export const endExpiredSession = async (): Promise<void>;

/** AppShell calls this before its own signOut(), so RequireAuth's listener
 * treats the SIGNED_OUT event as intended and shows no notice. */
export const markUserSignOut = (): void;
```

`endExpiredSession()` does, in order:

1. Returns if a sign-out is already in progress.
2. `supabaseClient.auth.signOut({ scope: "local" })`.
3. `store.clear()` and `apolloClient.clearStore()`.
4. Navigates to `buildSignInPath({ path: current, reason: "EXPIRED" })`.

The in-progress flag resets on the next `SIGNED_IN` event.

```
/sign-in?next=%2Frecords&reason=expired
```

`reason` carries no user data. Any other value is ignored.

## 6. Error handling

| Failure | Detected by | User sees | System does |
|---|---|---|---|
| Token expired, forged or revoked | GraphQL error with `extensions.code = "UNAUTHENTICATED"` | Sign in with the expired notice | `endExpiredSession()`. The failed request's own error card never renders |
| WebSocket token rejected | Close code 4403 | Same | Same. No reconnect loop |
| Refresh token rejected by Supabase | `SIGNED_OUT` event not started by the user | Same | Same |
| User chooses Sign out | `markUserSignOut()` then `SIGNED_OUT` | Sign in, no notice | `store.clear()`, `apolloClient.clearStore()` |
| `signOut()` itself fails, for example offline | Rejected promise | Sign in with the expired notice | Stores cleared and redirect made regardless. Whether supabase-js removes the stored session on a failed call is unverified; T-4.4 checks it offline |
| Several requests fail at once | Second call finds the flag set | One redirect, one notice | Later calls return |

Text typed into capture is not kept (Q2, answered 2026-09-27). A session
revoked on another device ends here on the next request, not sooner (Q3).
