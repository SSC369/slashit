## 1. What works when this lands

`/search uber` and the Records search box find expenses by description and by
category word, alongside tasks, reminders and memories. A search by
meaning finds them too once the embed job has run: "food" finds "dinner at
Toit". `/search 850` finds every expense of exactly ₹850, first, as the
`SearchExpense` artboard draws. An expense's detail lists up to five records
close in meaning, as every other detail does. The Expenses tab gets its search
box (dev log D-12). A written answer to a question can cite an expense.

## 5. Internal contracts

```python
# search/interfaces/ports.py: one keyword added (Q1)
class SearchPort(Protocol):
    async def search_candidates(
        self, *, user_id: UUID, text: str, terms: Sequence[str],
        query_embedding: Sequence[float] | None, max_distance: float, limit: int,
    ) -> CandidatePageDTO: ...

# expenses/services/search_amount.py, pure
def amount_from_search(*, text: str) -> int | None:
    """The whole search read as one rupee amount, with an expense line's rules:
    "850", "₹850", "1,200", "850.50", "1.2k", "3 lakh". None for anything
    else, and for an amount past MAX_AMOUNT_PAISE."""

# expenses/public.py
ExpenseService.search_candidates(*, user_id, text, terms, query_embedding,
                                 max_distance, limit) -> ExpenseSearchPageDTO
ExpenseService.embedding_of(*, user_id, expense_id) -> tuple[float, ...] | None
```

The repository's query, after the reminders one:

- `matches` is the shared word-or-meaning expression, OR
  `amount_paise = amount_from_search(text)` when that is not None.
- `all_terms` is true for an exact amount match (Q2), so it ranks in 005 AD-3's
  top tier, above meaning-only matches.
- `word_rank` is 1.0 for an exact amount match with no word present, so it
  sorts with word matches, not after them.

`amount_from_search` lives in expenses, not capture: search reaches expenses
only through its port, and capture's `amount_reading` is capture's own. It is a
copy of capture's whole-amount rules, as search's `terms.py` copies 004's term
builder; C-33 runs both readers over one table of inputs so they cannot drift.

Q1 was answered A, so build plan AD-7 and the index's §4 carry change records
for the `text` keyword on 005's `SearchPort`.

## 6. Error handling

| Case | Result |
|---|---|
| The embed job's model call fails | Retries three times, then the vector stays NULL for the periodic backfill; words and amount still match |
| The queue cannot be reached on save | Logged; the save stands; the backfill queues it within ten minutes |
| A description edit while an embed runs | `set_embedding` writes only if the description is unchanged, as reminders |
| A search that is a number past the ceiling | No amount match; words and meaning only |
| A deleted expense | Never matched, never related, never cited |
