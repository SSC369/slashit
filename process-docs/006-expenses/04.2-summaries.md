## 1. What works when this lands

`/expenses last month` shows per-category totals, largest first, with share
bars and a grand total. `/expenses` alone shows this month. An empty period says
so with its date range; an unreadable period is refused, listing the accepted
ones. The Expenses tab opens on this month with a period picker and a summary
band above the table; the band, the table and `/expenses` give the same totals
for the same period.

## 5. Internal contracts

```python
# expenses/services/periods.py
class PeriodKey(StrEnum):
    TODAY, THIS_WEEK, LAST_WEEK, THIS_MONTH, LAST_MONTH, MONTH, THIS_YEAR, ALL_TIME

@dataclass(frozen=True)
class Period:
    key: PeriodKey
    start: date | None      # None only for ALL_TIME
    end: date | None        # inclusive
    label: str              # the pill and the band: "September 2026"
    phrase: str             # FR-26's sentence: "last week", "in September 2026"

def parse_period(*, text: str, today: date) -> Period | None
def picker_periods(*, today: date) -> list[Period]
```

`parse_period` lower-cases, trims and collapses spaces, then matches exactly.
Empty text is this month (FR-24). `ALL_TIME` comes only from the picker, since
FR-23's list is closed.

| Text | Range | Label | Phrase |
|---|---|---|---|
| `today` | today | Today | today |
| `this week` | Monday to Sunday holding today | This week | this week |
| `last week` | the Monday to Sunday before | Last week | last week |
| empty, `this month` | 1st to last day of this month | October 2026 so far | this month |
| `last month` | the month before | September 2026 | in September 2026 |
| `august`, `aug`, `sept` | the most recent such month not after today | August 2026; this month's own name reads as `this month` | in August 2026 |
| `this year` | 1 Jan to 31 Dec | 2026 so far | this year |

> Assumption: "so far" on this month and this year, as `SummaryStates` draws.
> The range still runs to the period's last day, so a confirmed future expense
> counts (PRD assumption under FR-22).

> Assumption: Today, This week and Last week as labels. No artboard draws them.

`picker_periods` returns, in order: Today, This week, Last week, This month,
Last month, the 12 months before last month by name, This year, All time.

```python
@dataclass(frozen=True)
class CategoryTotal:
    category: ExpenseCategory; total_paise: int

@dataclass(frozen=True)
class ExpenseSummaryDTO:
    period: Period; category: ExpenseCategory | None
    totals: list[CategoryTotal]   # non-zero only, largest first, ties in FR-9 order
    grand_total_paise: int; count: int

ExpenseService.periods(*, user_id) -> list[Period]
ExpenseService.summarise(*, user_id, start: date | None, end: date | None,
                         category: ExpenseCategory | None, label: str, phrase: str) -> ExpenseSummaryDTO
ExpenseService.summarise_text(*, user_id, text: str) -> ExpenseSummaryDTO | PeriodNotUnderstood
```

The sum is one query: `SELECT category, SUM(amount_paise), COUNT(*) ... WHERE
user_id = :u AND deleted_at IS NULL AND spent_on BETWEEN :start AND :end GROUP
BY category`, served by slice 1's `(user_id, spent_on)` partial index. Python
adds the grand total from the same rows, so the band's total and its cells can
never disagree.

## 6. Error handling

| Case | Result | Where drawn |
|---|---|---|
| `/expenses since diwali` | `ExpenseRefused(PERIOD_NOT_UNDERSTOOD)`, `refused` turn, text kept in the box | `SummaryStates`, FR-27 |
| A period with no expenses | `ExpenseSummary` with `count: 0`; the card shows the phrase and range | `SummaryStates`, FR-26 |
| The same in the Expenses tab | Band hidden; "No expenses recorded in {label}" | `ExpensesStates`, empty period |
| A category with nothing in the period | "No {category} expenses in {label}" | `ExpensesStates`, filtered |
| `expensePeriods` fails | The tab's error note with Try again; nothing else loads | `ExpensesStates`, error |
| `expenseSummary` fails while the list loaded | Band hidden; table shown | — |
| Signed out | 001's session-ended handling | `ExpensesStates`, no permission |

A summary makes no model call, so a provider outage never affects it.
