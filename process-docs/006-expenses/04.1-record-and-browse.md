## 1. What works when this lands

A signed-in user types `/add-expense ₹850 dinner with friends yesterday` and
sees the saved card with amount, description, category and date. A line with no
amount, no description, two numbers or a future date asks one question at a
time, and the date question opens a calendar. Another currency, an over-long
description and a model outage are refused with the text kept. Records shows an
Expenses tab with category chips, expense rows in All with the amount as status,
a detail page, an edit form and a delete confirmation, with every drawn state.
No totals and no search yet.

## 5. Internal contracts

```python
# capture/services/expense_capture.py
@dataclass(frozen=True)
class ExpenseDraft:
    amount_paise: int | None; candidates: list[int]; description: str | None
    category: ExpenseCategory | None; spent_on: date | None

def next_step(*, draft: ExpenseDraft, today: date) -> Ask | Save
    # In this order, per build plan §5:
    # no amount and no candidates -> Ask(AMOUNT)
    # two or more candidates      -> Ask(AMOUNT_CHOICE, candidates)
    # no description              -> Ask(DESCRIPTION)
    # spent_on > today            -> Ask(DATE, read_date=spent_on)
    # else                        -> Save
```

`capture()` order: the foreign-currency check runs on the raw text first, so
`$20 lunch` never costs a model call. Then the extraction call; a gateway failure
returns unmapped. Then the model's `currency`: anything but `INR` or null
refuses. Then `keep_candidates`: one kept sets `amount_paise`. Then the
description length check, then `next_step()`. Nothing is written before Save, or
before the pending row for an Ask.

`resume()` by kind:

| Kind | Answer accepted | On anything else |
|---|---|---|
| `AMOUNT` | `normalise_amount(answer)` > 0 | Same question again, with "Enter an amount such as 850 or 1,200.50" |
| `AMOUNT_CHOICE` | One of the stored candidates, sent as paise, or a typed amount | Same question again |
| `DESCRIPTION` | 1 to 200 characters. One extraction call reads the category; a failure saves as Other | Over 200: `ExpenseRefused`, pending row kept |
| `DATE` | Any ISO date, past or future, from "Yes" or the calendar | Same question again |

After each accepted answer the draft is updated and `next_step()` runs again, so
a line missing both amount and description asks twice, in order. Each question
replaces the pending row in one transaction.

`ExpenseService.update_expense` validates amount > 0 and description 1 to 200,
returning `ExpenseInvalid { field, reason }`. Any date is accepted (PRD FR-21).
A description change sets `embedding` to NULL; slice 3 adds the requeue.

## 6. Error handling

| Case | Result | Where drawn |
|---|---|---|
| Another currency in the text | `ExpenseRefused(FOREIGN_CURRENCY)`, no model call, `refused` turn | `CaptureStates`, FR-6 |
| Model says a currency other than INR | Same | FR-6 |
| Description over 200 | `ExpenseRefused(DESCRIPTION_TOO_LONG, length)`, text kept | `CaptureStates`, FR-13 |
| Gateway failure | Failure member unmapped; `refused` turn | `CaptureStates`, FR-14 |
| Model lists a number not in the text | Dropped by `keep_candidates`; zero kept asks AMOUNT | FR-3 |
| Model returns an unknown category | Saved as Other | FR-10 |
| Model returns an unparseable date | Treated as today | FR-7 |
| Late description, categorise call fails | Saved as Other | FR-10 |
| `expense(id)` for another user, unknown or deleted | `ExpenseNotFound` | `DetailStates` |
| `updateExpense` with amount 0 or description over 200 | `ExpenseInvalid` | `DetailStates` |
| `updateExpense` or `deleteExpense` on a deleted expense | `ExpenseNotFound` | `DetailStates` |
| `expense`, `updateExpense` or `deleteExpense` with a malformed id | `ExpenseNotFound` | `DetailStates`. Added 2026-10-03, dev log E-1 |
| An amount past the storage ceiling, in the line | `ExpenseRefused(AMOUNT_TOO_LARGE)`, text kept, `refused` turn | Capture refusal note, FR-2. Added 2026-10-03, E-2 |
| An amount past the ceiling, as an answer | The question asked again with the too-large copy | FR-2, E-2 |
| `updateExpense` with an amount past the ceiling | `ExpenseInvalid(TOO_LARGE)` | `DetailStates`, E-2 |
| An `/add-expense` line over 500 characters | Read under the 1,000 guard memory and search use; a description over 200 is `DESCRIPTION_TOO_LONG` | FR-13. Added 2026-10-03, E-3 |
| A chip answer | Sent as `chip:<paise>`, accepted only for a listed candidate; digits typed are always rupees; the turn logs the chip as `₹180` | FR-5. Added 2026-10-03, E-5 |
