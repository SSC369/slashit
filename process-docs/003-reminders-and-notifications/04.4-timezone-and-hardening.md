Migration in this slice: `0022_notifications_soft_delete`. Changed `notifications`: new column `deleted_at`, and the unread index rebuilt to skip deleted rows (see §3, decision 1).

## 1. What works when this lands

A user who changes timezone keeps every repeating reminder at its clock time in
the new zone, and every one-time reminder at its original moment. An hourly
check logs an error for any reminder that is more than 5 minutes overdue and
has not fired. Notifications older than 90 days leave the list. Firing can be
stopped with one setting. Every cross-slice case, X-1 to X-6, is tested against
a real database.

## 2. Requirements covered

## 5. Timezone change, step by step

```text
updateTimezone (identity), when the zone actually changed:
  save user_settings.timezone                          # commits
  defer "reminders.timezone_changed"(user_id) by name  # AD-6: identity never imports reminders
    queueing lock "tz:{user_id}"                       # a second change while one is queued adds nothing

reminders.timezone_changed(user_id)                    # service role; each write in the user's transaction
  zone = user clock's current timezone                 # read now, so the last change always wins
  for each live, not-done reminder of the user whose schedule_timezone != zone:
    repeating: schedule_timezone = zone
               next_fire_at = next_occurrence(spec, zone, after=now)
    one-time:  one_time_at unchanged
               schedule_timezone = zone; local_time and anchor_local_date read from one_time_at in zone
    snoozed_until: unchanged, it is a moment
    write only if updated_at is still what was read     # an edit made meanwhile wins
  log reminders.rezoned(user_id, moved_count)
```

A `fire_one` already queued for the old time finds `next_fire_at` changed and
fires nothing, through 4.2's `expected_due_at` check. The next sweep queues the
new time.

## 6. Reconciliation and purge

```text
reminders.reconcile, hourly at minute 30
  due = LEAST(next_fire_at, snoozed_until)
  lost = live, not-done reminders with due < now - 5 minutes      # 4.2's "late" line
  each: log error reminders.lost(reminder_id, user_id, due_at, minutes_overdue)
  log info reminders.reconcile(lost_count)                        # NFR-4 reads lost_count, target 0

notifications.purge_old, daily at 03:15 UTC
  UPDATE notifications SET deleted_at = now
   WHERE deleted_at IS NULL AND created_at < now - 90 days        # batches of 5,000 until none
  log notifications.purged(count)
```

`fire_one` moves `next_fire_at` forward on every firing, missed ones included.
A reminder still overdue after 5 minutes therefore has had neither a firing nor
a missed marker, which is what NFR-4 counts. No join to `reminder_firings` is
needed. Logs carry ids only, never reminder text (T6).

## 9. Error handling

| Failure | Detected by | User sees | System does |
|---|---|---|---|
| The rezone job fails | Exception | Old times until it succeeds | Retried 5 times; `reminders.rezone_failed` logged. The next timezone change queues it again |
| A reminder is edited while being rezoned | `updated_at` changed | The edit | The edit wins; that reminder is skipped and logged. The edit's own save used the new zone |
| Two timezone changes in quick succession | Queueing lock | Times in the last zone chosen | One queued job, which reads the current zone when it runs |
| Worker down | Reconcile, next hour after restart | Late or missed markers, as slice 2 | `reminders.lost` errors; the alert of PRD §9 |
| Purge fails part way | Exception | Old items stay a day longer | Next day's run finishes; each batch commits alone |

## 12. Risks

| Risk | Effect | Mitigation |
|---|---|---|
| Soft-deleted notifications are never removed | The table and its deliveries grow for ever | Measure row counts after launch; a hard-delete pass needs your decision and a change record |
| A zone change lands between a sweep and `fire_one` | That occurrence moves, not fires twice | 4.2's `expected_due_at` check; TC-4.7 |
| A daylight-saving jump on the day of the move | Next time skips or repeats an hour | `next_occurrence` owns AD-12; TC-4.1 runs in a zone with no DST and one with |
