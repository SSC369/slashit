# Implementation Sub-Plan 3 — Email and settings

Parent: [Implementation plan index](./04-implementation-plan.md)
Context: [PRD](./01-prd.md) · [Design](./02-design.md) · [Build plan](./03-build-plan.md) · [Dev log](./05-dev-log.md)

Migration in this slice: `0021_notification_time_zone`. Changed `notifications`, one column `time_zone`, new to the index (see §3, decision 3).

## 1. What works when this lands

A reminder that fires also arrives by email, unless email is off, the reminder
is more than a day late, or the user has had 50 reminder emails today. The
first firing past the cap puts "Email paused until tomorrow" in the panel. The
email's Open in Slashit link lands on the reminder, through sign-in if needed.
Settings holds the default reminder time and both switches, and warns once
when both are off. Email stays switched off until a sending domain is verified
(decision 2).

| FR-39 | 50 sent or queued emails per user per local day; the first firing past it writes one `email_paused` notification that day |
| NFR-2 | One `send_email` job per delivery, deferred as the notification commits; hand-off time logged |

## 3. Decisions taken for this slice

| # | Decision | Chosen, 2026-09-23 | Why |
|---|---|---|---|
| 1 | A signed-out reader follows the email link | Sign-in returns to the link. `RequireAuth` passes the path; sign-in and OAuth go back to it. Logged against 002 | The design's flow ends on the reminder's detail, not on Capture |
| 2 | No sending domain or Resend key yet (build plan Q9) | Build the whole path; `REMINDER_EMAIL_ENABLED=false` by default, so deliveries are written `skipped` and nothing is sent until a verified domain and key are set. Tests use a fake sender | Everything but the first real send is verifiable now |
| 3 | What the email job knows | `notifications` stores the reminder's `time_zone` beside `occurred_at`. The job reads only its own domain and identity | Notifications may not call reminders: reminders already calls notifications, and the graph stays acyclic (§6.3) |

Not in this slice: Resend's bounce and complaint webhooks (build plan §9). They
need a public, signed endpoint, which waits for a deployed URL. Failed sends
are logged.

## 5. Email, step by step

```text
NotificationService.publish (reminder kind), after the list row and pop-up row:
  settings = delivery settings (popups, email, timezone)          # identity
  email status:
    skipped  if REMINDER_EMAIL_ENABLED is false, email is off, or marker = missed
    skipped  if 50 emails queued or sent today, in the user's local day
             and, the first time that day, publish an email_paused notification
    queued   otherwise
  COMMIT, then defer notifications.send_email(delivery_id)
    queueing lock "email:{delivery_id}". A repeat publish finds the row and
    re-defers a still-queued delivery, so a crash between commit and defer
    is repaired by fire_one's own retry

notifications.send_email(delivery_id)     5 attempts, exponential backoff
  load the delivery; stop unless status = queued
  to = identity.get_account_email(user_id)
  compose subject, HTML and text from the notification alone
  POST https://api.resend.com/emails, Idempotency-Key: delivery_id
  sent: status = sent, provider_message_id, sent_at; log hand-off delay (NFR-2)
  error: attempts += 1; after the last attempt, status = failed; the list row stands
```

| Email | Subject | Body line |
|---|---|---|
| On time | Reminder: Call Mom | Today, 7:00 PM · Asia/Kolkata |
| Late | Late reminder: Submit timesheet | Sent late. This was due Sun 21 Sep at 6:00 PM, and Slashit could not send it on time. |

Both carry "Open in Slashit" to `{APP_BASE_URL}/records/reminders/{id}`, the
line "Done or snooze it in Slashit. You need to be signed in.", and the footer
"You get this because email reminders are on. Change email settings".

## 7. Internal contracts

```python
@dataclass(frozen=True)
class DeliverySettings:            # notifications' words
    popups_enabled: bool
    email_enabled: bool
    timezone: str

class RecipientPort(Protocol):
    async def email_address(self, *, user_id: UUID) -> str | None: ...

class EmailSender(Protocol):       # services/resend_sender.py implements it
    async def send(self, *, idempotency_key: str, to: str, subject: str,
                   html: str, text: str) -> str: ...   # provider message id
```

```graphql
updateReminderSettings(input: UpdateReminderSettingsInput!): UpdateReminderSettingsResult!
input UpdateReminderSettingsInput { defaultReminderTime: String, popupsEnabled: Boolean, emailEnabled: Boolean }
union UpdateReminderSettingsResult = ReminderSettingsSaved | InvalidReminderSettings
type ReminderSettingsSaved { settings: Settings!  showBothOffWarning: Boolean! }
```

## 8. Error handling

| Failure | Detected by | User sees | System does |
|---|---|---|---|
| Email disabled by configuration | `REMINDER_EMAIL_ENABLED` false | Nothing in the app changes | Delivery `skipped`; logged once per firing |
| Resend rejects or times out | HTTP error | Nothing; the list row and pop-up already landed | Retries 5 times, then `failed`, logged with the status code, never the address or text (T6) |
| No account email | Recipient lookup returns none | Nothing | Delivery `failed`, logged |
| Cap reached | Count of today's emails | "Email paused until tomorrow" in the panel, once | Later firings that day: `skipped` |
| Settings save fails | Network or 5xx | `SettingsFailed`: the control flips back, with the design's line | Store unchanged |
| Invalid default time | Interactor validation | Field error under the time | Nothing written |
| Session ended | Not authenticated | Session card | Sign-in, then back to Settings (decision 1) |
