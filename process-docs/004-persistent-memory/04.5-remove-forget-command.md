# Sub-plan 4.5 — Remove the forget command

> **Approved** by @user on 2026-09-27. Locked — changes require a change record (§7).

Parent: [Implementation plan index](./04-implementation-plan.md) ·
Context: [PRD](./01-prd.md) FR-24 to FR-28 struck · [Design](./02-design.md)

## Tables touched

`capture_turns`: migration `0031_drop_forget_turns` deletes past `/forget` rows.

## 1. What works when this lands

Chat has no `/forget`. A memory is forgotten only from its detail page in
Records, one at a time. Typing `/forget` gets 001's unrecognised-command reply.
No forget-all exists. Past "Forgot N memories" rows are gone from history.
"Keep the new one" on a conflict still forgets the old memory.

## 2. Decisions, 2026-09-27

| Question | Answer |
|---|---|
| What replaces `/forget all` | Nothing for now; one-by-one from the detail page |
| `/forget` typed after removal | Unrecognised command, like any other |
| Past `/forget` history rows | Deleted |
