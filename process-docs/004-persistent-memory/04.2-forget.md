`affected_count`, the scrub check constraint, outcome `memory_forgotten`.
`memories` gains no column; its tombstone constraint shipped in `0024`.

## 1. What works when this lands

Forget from a memory's detail page asks for confirmation naming the full text,
then the memory is gone from Records, lookups and counts. `/forget airline`
lists up to five matching memories to pick from, then confirms by name.
`/forget all` states the count and confirms. After any forget, capture history
shows "A memory was saved here and later forgotten" where the fact was typed,
and the `/forget` turn itself reads only "Forgot 1 memory". A test searches
every table for the forgotten text and finds nothing.

## 5. Internal contracts

```python
# memories/interfaces/ports.py
class TurnScrubPort(Protocol):
    async def scrub_turns_for_memories(self, *, user_id: UUID, memory_ids: list[UUID]) -> int: ...

# memories/services/memory_service.py
async def find_forget_candidates(self, *, user_id: UUID, text: str) -> ForgetCandidatesDTO
# ForgetCandidatesDTO(candidates: list[MemoryDTO] (<= 5), total_matches: int,
#                     forget_all: bool, all_count: int)
async def forget_memories(self, *, user_id: UUID, memory_ids: list[UUID]) -> MemoriesForgottenDTO
async def forget_all(self, *, user_id: UUID, expected_count: int
                     ) -> MemoriesForgottenDTO | MemoryCountChangedDTO
```

`forget_memories` does three things, in this order:

1. Keep only ids that are the caller's live memories. An empty result is
   `MemoriesForgottenDTO(count=0)`, and the resolver maps it to `MemoryNotFound`.
2. Scrub the turns, then tombstone the memories. Scrub first, so a failure
   between the two leaves the memory visible and retryable, never its words
   stranded in history. A retry finds the history already scrubbed, which is a
   no-op.
3. Record `memory_forgotten` once, with no text.

Forget never calls the model, so it works while the model is down.

```graphql
type ForgetCandidates { candidates: [Memory!]! totalMatches: Int! forgetAll: Boolean! allCount: Int! }
type MemoriesForgotten { count: Int! }
type MemoryCountChanged { message: String! count: Int! }
forgetMemory(id: ID!): MemoriesForgotten | MemoryNotFound                    # Records
forgetFromCapture(memoryIds: [ID!]!, forgetAll: Boolean!, expectedCount: Int!):
  MemoriesForgotten | MemoryCountChanged | MemoryNotFound                    # capture
```

`forgetFromCapture` is capture's, so the `/forget` turn is written by the domain
that owns history. `forgetMemory` from Records writes no turn: nothing was
typed.

## 6. Error handling

| Case | Result | Where drawn |
|---|---|---|
| `/forget` with no words | Nothing forgotten; "Type what to forget, or `/forget all`" | `CaptureStates`, as FR-26 |
| No match | `ForgetCandidates` with none; "No memory matches …" | `CaptureStates` |
| More than five matches | The five best, and "{n} more match; use more words or Records" | `ForgetPick` |
| Picked memory forgotten elsewhere before confirm | `MemoryNotFound`; the card says it is already gone | `ForgetConfirm` |
| Forget-all count changed since the confirm | `MemoryCountChanged`; the card shows the new count and asks again | `ForgetAll` |
| Request fails | The confirm stays open with 001's inline error; nothing changed | `ForgetDetailConfirm` |
| Backup window not yet known (deferred to launch) | The line reads "Copies in backups are erased on the regular backup schedule." `BACKUP_LINE` holds the exact window once set | all confirms, FR-29 |

Both wordings above were chosen by the user on 2026-09-25, each the
recommended option: the backup line stands in for the design's
`{backup window}` placeholder until launch, and a bare `/forget` explains itself
rather than asking a question.
