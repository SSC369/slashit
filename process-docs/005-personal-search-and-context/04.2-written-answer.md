## 1. What works when this lands

`/search when does my passport expire?` shows "Answer from your records" above
the groups: at most four sentences, each ending in a [n] that matches a row
below, and clicking either opens that record. A question nothing answers says
so in one sentence and shows nothing invented. With the model down or the
user's cap reached, the records still show with the amber "No answer this
time" line. A word search is unchanged and never calls the model. Search
events now carry counts and positions.

## 5. Contracts inside this slice

```python
# search/interfaces/ports.py
@dataclass(frozen=True)
class AnswerRecordDTO:
    number: int            # 1 to 10, the only way the model refers to a record
    record_type: RecordType
    text: str              # title, description or memory text
    detail: str            # "due Mon 13 Oct, pending", "fires Fri 10 Oct 9:00 AM", "saved 25 Sep"

@dataclass(frozen=True)
class AnswerDraftDTO:
    sentences: list[tuple[str, list[int]]]
    supported: bool

class AnswerPort(Protocol):
    async def write_answer(
        self, *, user_id: UUID, question: str, today: date, records: list[AnswerRecordDTO]
    ) -> AnswerDraftDTO | None: ...     # None: any gateway failure (FR-19)

class UserTodayPort(Protocol):
    async def today_for_user(self, *, user_id: UUID) -> date: ...
```

```python
ANSWER_SCHEMA = {"type": "object", "properties": {
    "sentences": {"type": "array", "items": {"type": "object", "properties": {
        "text": {"type": "string"}, "sources": {"type": "array", "items": {"type": "integer"}}},
        "required": ["text", "sources"]}},
    "supported": {"type": "boolean"}}, "required": ["sentences", "supported"]}
```

The instruction states: answer only from the numbered records; cite every
sentence; at most four sentences; `supported: false` and no sentences when
the records do not answer; never mention a record by its number in the text.
Terse, per 001's dev log I-1.

`check_answer` rules, in order: drop any sentence whose sources are empty or
include a number outside 1 to the records given; keep the first four; if none
remain, or `supported` is false, the result is `no_support`. Citations become
1 to n in order of first use, so the markers always read [1], [2] top down.

Events, numbers only:

| Event | Properties |
|---|---|
| `search_run` | `result_count`, `group_count`, `is_question`, `answered`, `no_support`, `meaning_unavailable`, `answer_unavailable` |
| `search_result_opened` | `position`, 1-based down the card |
| `answer_citation_opened` | `citation` |

## 6. Error handling

| Failure | Result |
|---|---|
| Any gateway failure on the answer call, the per-user cap included | `answerUnavailable: true`, records as slice 1 (FR-19) |
| The model returns malformed JSON | The gateway's `MalformedResult`, treated as above |
| Every sentence fails the check | `noSupport: true`, no sentence shown (FR-18) |
| A cited record falls outside its group's five | Pinned in, replacing the lowest uncited hit (AD-5) |
| `recordSearchEvent` with a kind not in the list, or a position under 1 | GraphQL validation error; the event is dropped, the UI unaffected |
| An event write fails | Logged; never surfaces to the user |
